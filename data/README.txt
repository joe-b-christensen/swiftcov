SwiftCov benchmark data: provenance
===================================

The real benchmark inputs used in the SwiftCov preprint are in this folder as compact lossless encodings (22 MB).
gen_data.py rebuilds the BED files from them, in streaming chunks, and checks the row count, byte count and sha256
of each against curation.json. Rebuilding needs no download and no third-party Python packages.

READS
-----
Google Brain Genomics Sequencing Dataset for Benchmarking and Development: HG002 HiSeqX PCR-free, source-labelled
30x, aligned to GRCh38 (Baid et al., doi:10.1101/2020.12.11.422022).

  BAM: https://storage.googleapis.com/brain-genomics-public/research/sequencing/grch38/bam/hiseqx/wgs_pcr_free/30x/HG002.hiseqx.pcr-free.30x.dedup.grch38.bam
  BAI: the same URL with .bai appended. The full BAM is 62,927,996,476 bytes.
  The source generation, ETag, exact chromosome byte ranges and downloaded-range sha256 are in curation.json.
  Retrieved: 2026-10-11.

  Development: all 12,459,679 mapped, positive-span chr21 alignments, 603,365,318 BED bytes.
  Holdout:     all 10,528,760 mapped, positive-span chr22 alignments, 514,523,454 BED bytes.

No region tiling, simulated reads, repetition, downsampling, deduplication or MAPQ filtering. The chromosomes are
disjoint, but both come from the same sample and share the genome-wide query annotation: the holdout is a different
chromosome, not a new cohort. BAI pseudo-bin counts exactly equal the retained mapped records; the 19,987 chr21 and
16,921 chr22 excluded records are exactly the BAI unmapped counts. First starts and last ends are in curation.json.
Retained span over chromosome length gives depths of 38.7566x (chr21) and 30.4318x (chr22); the source's 30x label
does not imply uniform depth in every region.

Transformation. BED start is the BAM zero-based POS; end is start plus the reference-consuming CIGAR M/D/N/=/X
lengths. Every alignment is kept, including secondary, supplementary and duplicate-flagged alignments and both
overlapping mates. Mapping quality becomes the BED score and the original +/- strand is kept. The read name is
replaced by the stable unique identifier HG002_chr21_1 etc., in the original coordinate-sorted BAM order. Query
sequences, base qualities, CIGAR block structure, mate linkage and read names are not included; a digest of the
original names is in curation.json. CIGAR spans, not split blocks, are the intended intervals. Tiny BAM and -split
cases are in the random-input check.

Compact format. Each chromosome has three independent XZ streams, with one entry per retained alignment:
  delta32  unsigned little-endian 32-bit start differences (the first relative to zero)
  span32   unsigned 32-bit reference span lengths
  meta16   unsigned 16-bit values, MAPQ in bits 0..7 and reverse strand in bit 8

ANNOTATIONS
-----------
RefSeq: the assembly-matched hg38 UCSC RefSeq table.
  https://hgdownload.soe.ucsc.edu/goldenPath/hg38/database/refGene.txt.gz
  Primary chr1..chr22, chrX, chrY and chrM records: 78,363 transcript spans (refseq_transcripts.bed.xz, 5,473,706,873 bp)
  and 811,314 transcript-exon records (refseq_exons.bed.xz, 265,644,815 bp, including natural isoform overlap). RefSeq
  IDs, strand and overlapping isoform and exon records are kept. Scores are zero because the table has no BED score.
  Sorted by chromosome, start, end and accession; no coordinate extension.

Exome targets: Twist Bioscience Core Exome target regions from UCSC's hg38 Exome Probesets track, 192,264 BED3 records
spanning 33,167,129 bp (exome_targets.bed.xz). All coordinates are kept and sorted, with no padding.
  https://hgdownload.soe.ucsc.edu/gbdb/hg38/exomeProbesets/Twist_Exome_Target_hg38.bb
  Track documentation: https://genome.ucsc.edu/cgi-bin/hgTrackUi?db=hg38&g=exomeProbesets
  data/tools/acquire_source.py decodes the BigBed with the Python standard library and reproduces the sorted BED's
  sha256. The WGS reads were not produced with this capture panel: the workload asks for coverage of a real exome
  design by real WGS reads.

SCOPE
-----
The benchmarks are whole-chromosome WGS interval workloads against genome-wide annotations, not whole-genome
throughput measurements. Query rows off the read chromosome have zero coverage from these reads:

  chromosome   RefSeq transcripts   RefSeq exons      Twist targets
  chr21        1,091 of 78,363      9,713 of 811,314  1,994 of 192,264
  chr22        1,660 of 78,363      17,215 of 811,314 4,010 of 192,264

Every workload uses the annotation or targets as -a and the chromosome's reads as -b. Per-chromosome annotation
counts are in curation.json. The synthetic sets generated by gen_data.py are labelled as synthetic.

REBUILD FROM THE ORIGINAL SOURCES
---------------------------------
In an empty scratch directory outside data/, with the Python 3 standard library:

  python3 data/tools/acquire_source.py --source-dir /scratch/swiftcov_sources
  python3 data/tools/curate_source.py --source-dir /scratch/swiftcov_sources --output-dir /scratch/swiftcov_rebuilt

This downloads about 1.9 GB of indexed BAM ranges plus the annotations, checks the source hashes and recreates the
exact compact streams and BED hashes. The annotation URLs are mutable: a file that no longer matches its recorded
hash stops the script.
